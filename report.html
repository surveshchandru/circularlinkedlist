Problem Definition

What are we building?

A music player that lets you add, remove, search, sort, and navigate songs in a playlist. After the last song plays, it automatically wraps back to the first — just like a real music app. This wrap-around behaviour is the reason we chose a Circular Linked List.

🔄

Why Circular Linked List?

The last node points back to the first. This gives us free, automatic looping — no index reset needed.

📦

Song ADT (Data Node)

Each song stores: title, artist, genre, duration, and a next pointer to the next song.

↩

Stack for Undo

Every add/delete is saved on a Stack. One press of Undo reverses the last action.

🎯

Queue for Requests

Fans can "request" songs that get added to a queue. They play in the order they were requested (FIFO).

Insert at End — O(1) (core code idea)

def insert_end(song):
    if list is empty:
        head = song
        song.next = song          # points to itself
    else:
        tail.next = song          # old tail points to new song
        song.next = head          # new song points to head (circular!)
        tail = song               # update tail pointer

Delete by Title — O(n) (core code idea)

def delete_by_title(title):
    prev = tail; cur = head
    for each node in list:
        if cur.title == title:
            prev.next = cur.next  # skip over the deleted node
            return cur
        prev = cur; cur = cur.next
    return None                   # not found

Stack & Queue

Stack — Undo History (LIFO)

Last In, First Out. Every add/remove gets pushed. Undo pops the top. 

# Push when a song is added
stack.push(("ADD", title))

# Pop to undo
action = stack.pop()
if action == "ADD":
    playlist.delete(action.title)

Queue — Song Requests (FIFO)

First In, First Out. Uses a circular array — rear wraps to front. 

# Request a song
queue.enqueue("Hotel California")

# Play the next requested song
title = queue.dequeue()
play(title)

# Full check: (rear+1) % cap == front

Searching Algorithms

Linear Search — O(n) · works on unsorted data

Checks every song one by one until found.

for song in playlist:
    if song.title == target:
        return song   # found!
return None           # not found

Used for: search by title and search by genre

Binary Search — O(log n) · needs sorted list first

Cuts the search space in half each step. Much faster for large playlists.

lo = 0, hi = last
while lo <= hi:
    mid = (lo + hi) / 2
    if songs[mid] == target:  return songs[mid]
    elif songs[mid] < target: lo = mid + 1   # go right
    else:                     hi = mid - 1   # go left

Used for: search by title (sorted) and search by duration (sorted)

MethodBest CaseWorst CaseUse When
Linear SearchO(1)O(n)Data is unsorted

Sorting Algorithms

Bubble Sort — Sort by Title

Compares adjacent songs and swaps if out of order. Repeats until sorted.

for i in range(n-1):
    for j in range(n-i-1):
        if songs[j].title > songs[j+1].title:
            swap(songs[j], songs[j+1])  # bubble up

Insertion Sort — Sort by Duration

Picks each song and inserts it in the correct place in the already-sorted portion.

for i in range(1, n):
    key = songs[i]
    j = i - 1
    while j >= 0 and songs[j].duration > key.duration:
        songs[j+1] = songs[j]   # shift right
        j -= 1
    songs[j+1] = key           # place in correct spot

Selection Sort — Sort by Artist

Finds the smallest (alphabetically) remaining song and places it next. Fewest swaps.

for i in range(n):
    min_pos = i
    for j in range(i+1, n):
        if songs[j].artist < songs[min_pos].artist:
            min_pos = j
    swap(songs[i], songs[min_pos])   # put smallest in position i
